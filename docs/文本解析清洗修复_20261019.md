# V0.2.5 文本解析与清洗

## 原因与实现

用户提供的桌面版喂养TXT含标题、来源、统计、分组及“### 示例”编号。V0.2.4逐行要求“称呼：内容”，在首行失败。此问题不是字数或文件大小限制。

V0.2.5增加纯本地确定性预处理，不调用模型、不联网上传原文：

- 识别这份桌面喂养格式的标题说明区、分组和示例编号，记入排除记录；空行单独统计。
- 支持中英文冒号、【称呼】/方括号称呼、部分时间前后缀与独立时间行；未识别的任意导出格式不保证支持。
- 正文折行与已知喂养格式的字面量`\n`合并为空格，统计合并数。普通文本的字面量`\n`不改写。
- 不猜测两方身份；提供候选称呼手动匹配。未知内容按原行号保留，必须逐段归类/明确排除，或返回编辑。
- 消息、待处理、排除记录均分页；长原文保留在页面内存，不整份送入视图。可撤销逐段处理；修改内容或称呼撤销旧授权。
- 辅助脱敏手机号、证件号、长号码及邮箱；不保证识别所有隐私。预览与提交内容一致。
- 不自动删除英文/重复消息，不翻译，不判断问答语义是否优质。显示计数提醒用户核对。
- 保留1MiB UTF-8大小、双方消息、至少2条、独立授权、用户/角色隔离及存储容量保护。

后端仍使用原严格解析器接收中性称呼`0/1`的已核对文本，不放宽身份校验和导入授权。此次前端修复无需修改云函数环境变量或部署后端。

## 整份用户文件本地验证

输入143622字节，去BOM后95393个JS字符；输出3028条消息，双方各1514条，待处理0段。排除1533行已知说明/编号/分组及1522行空行，合并37处正文换行。

疑似纯英文消息734条，完全相同的重复消息1805条（按说话人+脱敏后正文，相同内容首次之后计数），全部保留。这些是格式/字面统计，不是语义质量结论。原文件不覆盖、不修改。

来源是公开/合成数据整理而非个人微信历史；部分问答不连贯。仅持有文件不能证明拥有全部商业使用许可。导入之前应核对数据来源与所需许可，且不将素材经历认作用户事实。

提供的清洗版TXT为110858字节，以“用户：/女朋友：”标记，供旧版也可手动导入。选两方称呼分别填“用户”“女朋友”。清洗并非模型微调。

## 验证边界

自动测试覆盖格式、原行号、未知内容阻止保存、手动处理撤销、时间正文保护、脱敏一致、授权门槛及1MiB长文本；其wx为测试替身，不代表真机原生文件选择成功。

使用`scripts/inspect-import.mjs`对实际TXT执行全文件解析，仅输出摘要计数与哈希；可选输出新清洗TXT且禁止覆盖现有文件。原文件不加入源码和测试仓库。

本轮不向云端存入用户资料，不自动接受资料授权，不调用付费模型，不代表正式公开发布或语义风格验收。开发者工具预览/扫码结果以交付记录为准。

本地完整检查143项通过，前端约520KiB。微信开发者工具真实输入/点击测试完整载入95393字，解析3028条，待处理0，消息预览152页、末页8条；排除记录77页。截图及脱敏验收记录见任务deliverables/20261019-wechat-0.2.5-cleaning。测试只检查本地清洗，停留未授权状态，未保存资料或调用模型。
