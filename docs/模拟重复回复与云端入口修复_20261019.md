# V0.2.7 模拟模式与重复回复修复

## 原因

用户手机截图顶部为“本地模拟·非真实模型”，每条回复标记模拟模板。旧安装默认demo；“是你？”、“？”、“你是什么人”没有命中已有问候/身份规则，统一落到理性人格固定兜底。不是凭截图证明GLM-4.7重复，也没有证据应删除历史。

另外本地模板的检索来源被显示为“送入模型的参考”，与实际没有模型调用相矛盾，长引用块也反复挤占聊天界面。

## 修改

- 全新、无模式偏好且无本地数据的安装默认cloud。云端报错不回落demo；仍受可信微信身份、白名单、服务端开关及明确授权约束。
- 已有本地数据但未选过模式，保持demo显示，防止升级后误以为资料丢失。显式模式偏好优先。损坏本地索引不会因为默认切云端而被覆盖。
- 聊天页/列表增加真实AI切换入口。用户阅读计费、数据去向及本地/云端独立说明后手动确认。仅切换模式并回到会话列表，不自动同意隐私/保存，不上传或合并本地资料。
- 云端需重新选择已有云端角色或创建角色。本地角色、历史、资料保留；切回本地可继续查看。这个版本不做未经授权的历史搬运。
- 会话带来源模式；模式变化时拒绝拿旧会话ID查另一空间，提示返回当前会话列表。云端加载失败也仍显示云端，不把bootstrap为空误标成本地模拟。
- 模拟模式对“是你？”、“？”、“你是什么人”分开处理；一般兜底避开紧邻的相同模板，仍明确显示模拟模板，不伪装推理。
- 本地引用标明“未送入模型”；云端标“本轮提交模型的参考”，不声称模型一定采纳。未知历史模式不猜测已发送。
- 参考块默认折叠，点击展开；用“消息”而非原始TXT“行”指代清洗后参考序号。旧正文和出处不改写、不去重，不把旧模拟答案冒充新模型答案。

## 验证

单元/页面测试覆盖新装默认云端、旧空间保持、确认/取消切换、不自动上传、失败不回退、错误模式ID拦截、原始请求保留、引用标签、重复加载不追加重复消息及截图中的三种输入。真实开发工具、云端连接及模型回归结果以本轮交付记录为准。不同模式角色数量不会被误当作数据丢失。

## 全站每日上限追加需求

用户明确要求全站调用提高到30万次，按每日全站模型调用尝试数理解。服务端 DAILY_MODEL_CALL_LIMIT 校验上限由10000扩大至300000，默认值仍为100；个人 CHAT_DAILY_USER_LIMIT 保持30，截图个人每日10次及原有限流、白名单不变。bootstrap增加只读 globalDailyCallLimit 字段，用于核对已生效的服务器配置，不泄露密钥或用户标识。

必须同步修改云端已有 DAILY_MODEL_CALL_LIMIT=300000，不能只改代码，也不能重复新增同名Key。现有每日计数不清零。该上限不是金额预算、并发容量或免费额度，聊天、OCR及已发出但失败的模型请求都可能占用。没有进行30万次压力测试，也没有扩大白名单或执行公开发布。

187项单元/页面测试通过，包含300000被接受、300001/零/非整数被拒绝、默认值不变及全局耗尽不回退模拟。真实开发工具、云端配置及模型回归结果以本轮交付记录为准。无需重设密钥；此版本不保证所有问句都不可能重复。

## 实际云端验收

assistantApiV2已由官方CLI部署成功；在云开发控制台仅修改已有DAILY_MODEL_CALL_LIMIT为300000，未改其他环境变量。实际bootstrap返回globalDailyCallLimit=300000、chatDailyLimit=30。真实GLM-4.7对虚构角色的“是你？”、“？”、“你是什么人”三轮均成功且各不相同；原生聊天页mode=cloud、6条消息、无加载错误。个人剩余额度28→25，清理了本轮创建的临时角色及会话，原有角色/会话数量保持1/1。此前额度耗尽的失败报告另行保留，不冒充首次成功。

原有私人会话的额外只读抽检未获自动审批通过，因此没有继续读取，需要用户另行明确授权；合成角色验收不等于已验证所有私人资料上下文、真实手机或并发容量。未进行30万次请求测试。
