# 云端加载修复与首轮聊天验收 · 0.2.2

日期：2026-10-18（北京时间）。工程 项目根目录；函数 assistantApiV2；目标环境 g030411-d6gbju74084607dd0。

## 问题与复现

用户截图显示聊天页空白、“服务暂时不可用”、输入有草稿但发送禁用。检查时实际云端开关与白名单通过，个人每日30轮；页面role/bootstrap未加载，云端授权已同意但会话保存未开启，没有生成任务。

会话详情与bootstrap分别顺序调用均成功；按旧页面的并行方式重复3组，均有一个返回SERVICE_UNAVAILABLE。当前存储实现的读取也会执行维护及写回同一用户事务文档；页面并行调用触发的加载竞争已复现。未通过原始错误/日志断言某个具体数据库SDK错误码，也不是已证实的模型故障。

## 修复

- 聊天页的bootstrap与会话详情改为顺序读取；会话列表同样处理。
- 同一页面重复加载合并为一个任务，避免生命周期和手动刷新重叠。模式变化不复用旧模式任务；聊天页已卸载后不继续应用结果。
- 分开记录页面加载错误与生成错误；加载恢复清除旧加载错误，不清空草稿或掩盖生成失败。
- 新增加载状态与“重新加载会话”入口；加载失败/进行中不允许新生成；不自动重发聊天或确认授权。
- 版本升为0.2.2；服务端审核模式、白名单、密钥、额度和用户数据未被本次修复修改。

新增5项页面回归检查，完整类型检查、构建、102项测试和15页前端边界检查通过。新增测试使用明确标注的wx/云传输替身，不能替代真实云端证据。

## 真实验证

重新编译后原会话页实际加载成功。官方SDK直接callMethod加载调用遇到兼容错误，没有把该错误算成成功；随后使用正常“返回列表→重新打开原会话”流程完成3次验证，均有角色与bootstrap、无加载错误、模型开启。此阶段没有代为发送消息或开启保存。

用户随后手动确认使用与隐私说明及会话保存，并发送一次“你好”。仅读取原请求和原会话确认：

- 当前为cloud模式，accepted=true、historyEnabled=true、enabled=true。
- 最新任务SUCCEEDED，errorCode为空，没有待重试请求。
- 云端会话共2条消息，用户消息与cloud模式AI消息各1条。
- 每日上限30，剩余29；检查过程没有重新生成或重复发送。

这是首轮实际小程序调试会话→V2云函数→配置模型→存储消息→前端气泡链路成功。未记录聊天正文、OPENID、密钥或白名单；不能据此声称已完成50轮、真机扫码、多微信账号隔离、长期稳定性、高并发或公开上线验收。
