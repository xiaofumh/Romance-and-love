# 相伴 V0.2：开发与验收手册

日期：2026-10-18。工程：`项目根目录`。内部开发版，未上传或发布。

## 1. 实现范围

用户在微信小程序内直接与AI朋友或伴侣角色持续聊天，不是微信联系人机器人，也不再以三条回复建议为主流程。不重新训练模型；使用角色卡、近期消息、已确认记忆与历史片段检索。AI身份持续可见，禁止冒充历史资料中的真人。

- 四个主入口：聊天、角色、资料、我的。
- 二/三级：聊天窗口→会话设置；角色列表→关系/人格/详情创建向导；资料→导入→脱敏预览→授权确认；资料详情与角色独立记忆。
- 角色关系与人格独立选择，可编辑描述与边界。昵称首字/文字头像，不包含上传头像或生成图片。
- 每个角色可创建多个会话。短期消息仅取当前会话；同角色共用其已确认记忆与授权资料，不共用其他角色资料。
- 手动粘贴或选择UTF-8 TXT。明确映射双方称呼，严格解析，不猜测原始微信数据库格式，不读取私人聊天、图片、语音或压缩备份。
- 先预览手机号/邮箱/证件号/长号码辅助脱敏结果，再单独确认使用权。原始TXT文件不上传，发送审阅后的结构化文本；姓名、地址等必须人工检查。
- 候选记忆不参与推理；用户确认并开启记忆后才加入该角色上下文。记忆修改使用版本校验。可从资料详情手动添加带来源关联的候选事实。
- 消息长按复制标注AI；可查看本轮送入模型的参考资料。这表示提供给模型的片段，不证明模型实际引用、事实正确或已联网核实。
- 导出自己的陪伴数据为本地未加密JSON；用户另行点击后才打开分享选择，不自动外发。导出副本的保管/删除由用户负责。
- V0.1建议工具及其档案/历史作为兼容入口保留，不改写旧用户资料。

## 2. 运行和体验

在微信开发者工具打开 `项目根目录`，不要打开 `D:\` 根目录。构建入口仍为 `dist/miniprogram/`，新AppID保持不变。

```powershell
node scripts/check.mjs
```

首次体验：角色→右上角＋→选择关系→人格→填写昵称/描述/边界→手动阅读并确认说明→保存→新建聊天→分别确认使用说明及会话保存→发送消息。

资料可不导入，直接聊天。记忆默认关闭；“我的”手动开启后，资料→选择角色→记忆→存候选→确认事实。资料导入中可用虚构示例测试，勿拿真实第三人隐私验收。

当前默认 `demo`：固定模板，不是GLM推理，不收费，不上传；演示存储仍为当前设备的一个演示身份，不能用它证明双微信账号隔离。模拟回复和模式条明确标注。

## 3. 真模型接入与发布前缺口

生产适配器复用现有BigModel官方GLM-4.7配置；陪伴聊天调用 `Provider.chat`，外部模型使用`response_format: {type: 'text'}`，返回纯文本，服务端校验后包装为`{text}`。历史assistant消息也为纯文本，避免格式冲突。仅兼容通过严格校验的旧`{text}`外壳，不静默丢弃额外字段；旧版三条建议仍使用严格JSON。超时、长度、审核、预算、归属检查与不重复提交仍生效，不增加自动重试或模型训练。

仍缺：云环境ID、服务端安全配置（新密钥、用户HMAC秘密、审核凭证、运营与投诉信息）、实际云函数部署及数据库权限验收。此前在聊天中暴露的模型密钥应轮换，不写进前端/源码/文档。后续已按用户授权在进程环境中使用API进行真实测试，结果见修复记录；不再把本机真实API测试称作小程序云端验收。

1. 在 `src/miniprogram/config.ts` 配置环境ID后构建。默认仍demo，用户在“我的”明确选择云端模式。
2. 将服务端参数配置到云函数环境，不提交 `.env`。`.env.example` 增加 `CHAT_DAILY_USER_LIMIT=100`；全站 `DAILY_MODEL_CALL_LIMIT=100` 为调用次数预算，不是人民币硬限额。
3. 部署 `dist/cloudfunctions/assistantApi` 和 `assistantCleanup`，启用定时清理。数据库集合 `assistant_users` / `assistant_budgets` 禁止客户端直接读写；服务端也需本实现的身份/归属验证，不能只依赖数据库客户端规则。
4. 用两个真实微信账号检查查询、猜ID、删除、导出及实际模型请求上下文；再测试同账号多角色、双设备并发、网络中断与删除竞争。
5. 本机先前50轮真实API测试仅6轮被旧协议接收。协议修复后，48条已捕获响应离线回放、73项自动检查与6轮真实连续聊天通过，但完整50轮复测、原生小程序云端链路和生产内容审核仍未验收。详见[协议修复与复测](聊天协议修复与复测_20261018.md)。
6. 运营主体、用户年龄适配、内容审核、服务商数据保留/训练用途、适用规则与微信审核材料需发布前确认。不得承诺一定过审或第三方零保留。

## 4. 代码结构

| 路径 | 责任 |
| --- | --- |
| `src/shared/companion.ts` | 角色/消息/资料/记忆类型、严格校验、保守解析与辅助脱敏 |
| `src/server/companion.ts` | 会话/角色CRUD、资料检索、记忆、发送状态机、权限、删除与导出 |
| `src/server/companion-prompt.ts` | 仅服务端的AI陪伴提示与消息组装 |
| `src/server/providers.ts` | 同一安全HTTP适配器，建议与陪伴两种协议 |
| `src/server/state.ts` | 可选companion状态迁移、到期清理、全局版本失效 |
| `src/cloud/index.ts` | 微信可信身份→HMAC uid；客户端不能覆盖 |
| `src/miniprogram/pages/*` | 15个实际页面；9个新陪伴页面+6个旧页面 |
| `tests/companion.test.ts` | 跨用户/角色/会话上下文、取消/删除竞争、到期、幂等、预算 |

前端只包含demo规则和业务控制；真实系统提示与密钥不打入小程序。`scripts/verify.mjs`检查两类服务端系统提示均未泄露到前端。

## 5. 隔离与生命周期

- 云函数通过 `getWXContext()` 获取身份，uid来自AppID+OPENID的服务端HMAC，不接受客户端userId。HMAC不是正文加密。
- 每用户一份事务文档，资料先按该用户文档与roleId筛选，再做中文字符二元片段的词面排序；最多3个相关片段，不检索全站内容后再过滤。无付费向量数据库，无全局共享记忆缓存。
- 最近12条当前会话消息进入上下文，单条截取最多600字；角色记忆仅confirmed、开关开启时使用。检索语义能力有限，近义改写可能漏检，不能据此称“已学会某个人”。
- 用户提交的角色、历史、消息和记忆均是数据，不是更高优先级指令。提示防注入不是隔离边界，真正边界由服务端归属检查及每用户事务实现。
- 无正文chat job按uid+客户端请求ID派生，绑定输入哈希，重复请求复用状态。返回成功时成对提交用户/AI消息；失败不保存该轮正文，也不扣体验成功额度，但供应商可能计费。
- 同用户陪伴请求同时最多一条；每分钟最多12次尝试。每用户默认100次成功/日，仍受全站100次尝试/日限制，先到可能耗尽共享测试预算；应按运营容量调整。
- 资料、记忆、设置或授权变更增加revision并取消在途回复。预算等待后、模型调用前再验证一次；已经发给供应商的请求无法召回。迟到结果不得写回。
- 删除资料清空曾将它作为模型参考的会话正文，以及关联记忆影响的会话；删除/修改记忆清空所属角色会话正文；关闭记忆会清空所有陪伴会话正文。均有用户提示。
- 撤回授权不直接删除旧数据，停止新调用、关闭保存与记忆。重新授权但未开启记忆时，旧memoryUsed回合不进入新的短期上下文，后续新聊天可以继续多轮。
- 同一事实可能独立存在于其他资料中；须分别删除，不能保证语义相同的事实自动在所有来源消失。导出副本和供应商数据不能由本应用撤回。
- 删除全部陪伴内容仍保留48小时内无正文状态，防止清空数据重置今日成功额度/重复计费。删除账号业务数据后停用当前身份。

## 6. 开发版容量与保留

| 项目 | 本版本上限 / 期限 |
| --- | --- |
| 角色 / 会话 | 6个 / 12个（每用户） |
| 会话正文 | 最近40条 / 最长30天 |
| 当前输入 / AI文本 | 各最多1200字 |
| 资料 | 6份/角色，TXT/文本最多1MB（1024KB）、至少2行，不另设字数、行数或每行字数上限，30天 |
| 候选+确认记忆 | 合计10条/角色，每条100字 |
| 防重复状态 | 48小时，无原始消息正文 |
| 陪伴状态体积 | 最多4MiB UTF-8字节；全用户文档另有5MiB保护 |

到达总空间上限时需先导出清理，不能把各独立上限相乘当作保证容量。定时清理部署前，到期清除只在读写访问时运行。每用户单文档和全站预算单文档适合本次受控开发版，不是已完成高并发压测的生产架构；放量前需评估事务冲突、冷热分层、数据库与审核费用。

## 7. 验收边界

自动检查涵盖原有功能与新模块，具体数量以本轮 `scripts/check.mjs` 输出为准。新模块重点断言：A不能读/改/删B资源；B秘密及同用户另一个角色内容未进入A模型请求；候选不进入提示；会话短期上下文不混；文档/关联记忆删除、撤回恢复、过期、迟到回复、预算等待取消、并发、超时、幂等与历史长度。

页面逻辑测试在禁止动态字符串代码生成的VM内运行真实前端bundle，wx API为边界替身。不伪称真实用户操作、真实模型或真实云数据库测试。

微信开发者工具实际观察已确认：新首页、四个tab入口、三级角色创建向导正常渲染；观察到的启动控制台只有预加载/热重载警告，没有启动失败。尚不据此声称原生聊天、TXT系统选择、文件分享、真机和云端全链路通过。新隐私确认由用户手动操作，未由自动化替用户勾选。

手动剩余清单：发送/长按复制与输入键盘、返回后状态、双角色记忆隔离、TXT选取与脱敏预览、来源跳转、确认/修改/删除记忆提示、导出文件安全、弱网原请求恢复；最后再做双账号云端与真实GLM测试。
