## 发现的部署遗漏

云端 API 函数详情中的定时触发器表起初为“暂无数据”。官方开发者工具的函数部署成功，不代表触发器已经创建。构建目录中存在 `config.json` 也不足以证明调度已运行。

触发器需另外上传：

1. 在开发者工具编辑器中展开 `dist/cloudfunctions`，右键根目录，将当前环境设为项目实际使用的环境。
2. 右键 `assistantApiV2/config.json`，选择“上传触发器”；应收到成功提示。
3. 对 `assistantCleanup/config.json` 执行同样操作。
4. 到“云开发 → 云函数 → 版本与配置 → 函数详情”，刷新定时触发器表，逐一检查名称和表达式。
5. 用云端实际触发记录、任务状态与消息时间核验执行；手动调用不能充当定时器真实运行的证据。

| 函数 | 触发器 | Cron |
| --- | --- | --- |
| assistantApiV2 | companion-autonomy | `0 */1 * * * * *` |
| assistantCleanup | assistant-data-expiry | `0 */15 * * * * *` |

2026-10-31已通过开发者工具单独上传，并在真实云端函数详情核对了表中两项触发器名称与Cron。创建成功仍不等同于真实主动消息效果验收。

清理函数原执行超时为3秒，已调整为60秒并在云端详情核对保存成功。此调整避免默认超时过短，不代表所有批量负载都已通过实测。

API 定时入口仅在没有微信调用者身份、服务器触发来源为timer且事件类型为Timer时执行；客户端提交相同事件字段不能冒充后台调度。

## 真实云端验收结果

用户已在真实页面确认新版说明，服务端同意状态核对通过后才开始模型测试。保存与记忆开关沿用已有设置，脚本没有代接受说明或打开开关。所有模型输入均使用独立虚构角色，不使用用户原有角色的私人聊天。

35轮连续GLM云端调用全部成功，形成70条独立消息，分页读取70条、去重70条，近期工作缓存60条，最早消息仍可通过归档接口读取。实际模型请求的历史稳定在24条，即12轮；翻页没有把完整历史混入模型窗口。重复原请求后体验额度不变。

明确“记住：”产生待确认候选，API确认后来源可读，纠错为“迷迭香”后，模型回答新事实；旧消息没有继续作为纠错后的上下文。记忆检查命中本角色条目且不扣模型额度。跨角色引用消息来源、旧版本写入和客户端伪造身份字段均被拒绝，临时隔离角色已删除。这是同一真实微信账号下的角色隔离检查，不能替代双微信账号实测。

另完成2轮真实界面调用。第一轮请求实际成功，但测试脚本在原生事件生效前采样旧状态，导致即时气泡断言失败；已只读查询原请求确认成功，没有重放。修正测试采样时序后，另发一条不同测试消息，约124毫秒观察到待回复气泡，输入框清空，回复后下一条虚构草稿仍保留。该数值只是一轮自动化采样，不是响应时延承诺。修正的是验收脚本，不是用替身数据替换页面状态。

后台测试另发送1轮新话题作为前置消息，并在启用自主机制前退出所有聊天页。至此共38次真实普通回复调用成功（35轮批量、2轮界面、1轮后台前置）；独立检索、分页、隔离检查没有新增模型调用。后台模型尝试另外统计，不把页面前台接话冒充云定时器执行。

后台主动聊天保持北京时间23点至8点安静；不改时钟或绕过安静时段。触发器实际运行和主动消息自然度分别验收，模型选择WAIT不算主动消息自然度通过。

当前处于夜间，云端返回的下一次可主动时间为北京时间08:00；检查时没有主动消息或主动任务。虚构“研发验收070”角色暂留用于后续允许时段的后台调度验收，最多连续3次尝试、每日最多6次；验收完成后清理。尚未证明真实定时器已生成主动消息，也未证明物理清理已实际执行。

双微信账号隔离、真实30天持续运行、1000轮完整测试、精确提醒、规模吞吐仍需后续单独验证。

## 复核脚本

`scripts/cloud-v070-qa.mjs` 使用真实开发者工具自动化端口和 `wx.cloud.callFunction`，不模拟微信身份或模型输出。顺序执行，不并行运行多个阶段。需先由本人在真实页面确认说明；脚本遇到未确认、账号不匹配或付费请求结果未知时停止，不重新编号重发。

付费阶段必须显式附加 `--real-synthetic`：`--phase=chat` 为35轮批量测试，`--phase=native-send` 为界面测试，`--phase=arm-autonomy` 为后台前置话题。`--phase=isolation-checks` 与 `--phase=status` 不调用模型。`--phase=native-recover` 只读核对之前界面请求的结果，不证明首次时序断言通过。

测试角色标识、虚构输入和原始报告保存于运行目录的 `.local/cloud-v070-qa`，不得提交Git或打入发布包。复核已有测试时通过 `--workdir=<原测试工作目录>` 选择同一份私有夹具；不要换空目录重新创建角色来替代原请求查询。未提供该参数时使用当前工作目录。

当前夹具已启用后台测试，脚本会拒绝重复启用。后续先运行只读status阶段，核对initiative任务和主动消息，再决定清理虚构角色；不把定时器配置成功当成效果通过。
