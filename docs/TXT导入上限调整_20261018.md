# TXT导入上限调整 · 0.2.3

用户要求：TXT文件改为1M、字数20000，并重新生成临时预览码。

## 实现

- 文件上限按1MB（1024KB，即1048576字节）实现；文件选择后先检查大小，超限不读取。
- 文本上限20000，文件读取、粘贴文本解析、输入框及服务端ImportInput采用同一共享常量；不自动截断超限资料。
- 保留原有UTF-8/BOM处理、双方说话人映射、辅助脱敏、人工预览及单独授权。
- 同步更新隐私说明和容量文档；版本号0.2.3。

文件字节数和文本长度是两个独立限制：不表示允许把任意1MB文本全部入库。文本计数延续现有JavaScript字符串长度口径，包括称呼、标点和换行，部分emoji可能按多个单位计算。

本次未改变最多80行、每条正文400字、6份资料/角色、30天保存及整体存储容量限制。文本仍需整理成“称呼：内容”，不是任意微信原始导出格式。模型每次仍只接收最多3个相关片段，不会自动把整个20000字资料全部作为提示词。

## 验证

新增9项自动检查：解析/schema与业务接口20000/20001边界、文件1048576/1048577字节边界、超限不读取且保留草稿、文本超限、BOM、粘贴与输入框限制。TXT系统选择和文件内容在单元测试中明确mock，不冒充真机文件选择。

完整检查与实际部署结果，以本次执行记录和交付目录说明为准。未为这次导入上限验证发起付费模型调用，未自动导入用户资料或替用户确认授权。
