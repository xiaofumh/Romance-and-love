# 取消资料导入字数限制 · 0.2.4

用户要求取消TXT导入字数限制。本轮于2026-10-19继续完成中断前的开发。

## 改动

- 不再设置20000字、80行或单条400字上限；输入框maxlength=-1，前端和服务端按UTF-8字节统一检查。仍保留用户此前指定的单文件/单份文本1MB（1024KB）大小保护。
- 至少2行、双方称呼必须明确且不同、UTF-8/BOM、辅助脱敏、预览和单独授权要求保留。不能把任意微信原始备份自动解析为历史。
- 长文本完整保存在页面内存，不把整份大文本通过setData渲染；预览和已保存资料按小段分页，可前后翻页和跳页。显示分段不截断原始资料；关闭页面清理未提交的内存副本。
- 发往服务端的是用户确认的脱敏文本，使用0/1中性说话人标识，不发送原始文件或原始称呼。若脱敏后体积增长超过1MB，会明确提示拆分，不自动截断。
- 长参考消息分窗口检索，避免匹配位于末尾却只给模型不相关的开头；仍只取最多3段、每段最多240字，不将整份资料塞进每次对话。
- 本地模拟缓存分块保存，旧单文档缓存自动兼容迁移；新分块全部写成功后才替换索引，失败时保留旧快照。没有自动清除旧角色、记忆或聊天。
- 项目陪伴数据总空间保护从400000字节调整为4MiB，账号总文档保护从700000字节调整为5MiB。它们是本项目保护阈值，不是承诺的厂商配额或无限容量；资料数量与聊天等仍共用空间，空间满时须导出清理。
- 保留用户/角色隔离、删除/撤回取消、明确授权、模型预算及运行模式；本轮不改密钥、数据库权限、模型开关或个人额度。

## 验证

本地类型检查、构建、124项测试与15页前端边界检查通过。覆盖超过20000字、超过80行、长单条、准确1MiB与超限、分页重组不丢内容、末尾片段检索、云适配器/数据库SDK替身的大资料路径、4MiB/5MiB总容量保护、本地分块存储和失败保留旧快照。

单元测试中的微信文件/存储API、云SDK与数据库明确使用替身；不等于真实手机选文件、真实云数据库1MB保存或高并发均已通过。既有0.2.2首轮真实模型成功也不能代替本轮大资料验收。没有为本轮测试发起付费模型调用或导入用户私人资料。

部署和新二维码状态以本轮官方CLI输出及交付目录记录为准。旧文档中的20000字、80行、400字和小容量数字为历史记录，以本文及共享limits.ts为准。
