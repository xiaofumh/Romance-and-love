# V0.6研发版：外部记忆与主动相处维护说明

2026年10月30日。版本0.6.0-dev.1。本说明对应独立研发副本，当前活动工程及已上传V0.5.3未被替换。后台云触发器尚需真实部署验收，不把离线单元测试当成云端实际运行。

## 关键入口与修改边界

| 文件 | 负责什么 | 后期维护注意 |
|---|---|---|
| `src/shared/companion.ts` | 记忆类型、来源指针、输入校验、审计结构 | 新字段可选，兼容旧记录；客户端不能写入来源时间、说话人、来源数组 |
| `src/server/companion-memory.ts` | 去重、来源合并、衰减与检索、显式候选提取 | 纯规则、不读写数据库、不调用模型；修改规则需更新策略版本及回归测试 |
| `src/server/companion.ts` | 在可信用户事务中验证来源，接入回复/主动生成，保存候选和审计 | 先验证归属再排序；纠错与删除继续取消旧的在途结果 |
| `src/server/companion-prompt.ts` | 区分用户事实、历史人物、虚构设定和真实执行状态 | 模型只接收已选记忆；来源时间不是事件发生证明 |
| `src/server/state.ts` | 到期处理、来源级联删除与上下文边界 | 清理函数也使用本文件，保持其依赖轻量，避免把模型或Zod打包进去 |
| `src/server/autonomy.ts`、`src/shared/interaction.ts` | 主动资格、时段、次数、输入状态 | 单次普通回复、主动尝试及指定时间提醒不是同一机制 |
| `src/cloud/autonomy-tick.ts` | 云端扫描、请求幂等、失败退避 | 只自动处理已有用户允许的主动会话；真实部署后验证触发器与权限 |
| `src/miniprogram/pages/role-memory/` | 类型/重要程度编辑、来源提示、检索检查 | 保存仍是候选，确认由用户操作；不把规则分数说成真实性概率 |
| `src/miniprogram/pages/chat/` | 即时气泡、草稿保护、同步、来源入口 | 长按用户消息可存候选；只把ID放URL，AI消息仍仅提供复制 |

## 记忆策略 external-memory-v1

1. 每角色最多保存60条候选及确认记忆；每轮最多提供10条给模型。
2. 按可信用户状态、角色、确认、有效期、冲突及重复依次过滤。其他角色不出现在本轮诊断里。
3. 排序初值为：相关性0.60、重要程度0.15、时效性0.15、证据来源信号0.10。重要程度由用户选1至5，分数归一化。词法相关性采用标准化字符双字片段覆盖，不宣称已具备完整语义检索。
4. 明确边界优先；事件半衰期2天、偏好180天、普通事实90天。数值是可调整的工程初值，需要效果测试，不是认知科学定律。事件按来源消息时间或记录创建时间计算，不会因最新编辑就变成今天发生。
5. 无词法重叠的背景最多2条；称呼/明确边界不因长期未提就自然消失。重要程度不能绕过过期、候选或冲突过滤。
6. 同一来源重复使用不增加证据数量；来源最多保留4条。来源信号不等于独立证据真实性：不同消息可能转述同一个事实，仍需要用户核对。普通检索不更新确认时间或加强事实。
7. 修改内容后清除旧原文来源，改为手动纠正记录，除非重新提交包含新文字的合法来源。版本检查防止旧客户端覆盖新纠正；旧对话保留展示，但在纠错边界前的消息不再参与生成。

## 候选与来源

初版仅自动提取用户明确输入的“记住：……”和“请帮我记住：……”单行原文，最多100字。含引号、问号、假设性表达等保守跳过；普通自述不偷偷转成长期事实。候选主体默认未明确，需要用户核对。自动形成候选要求记忆开关已开启，且只在本轮成功保存时创建；失败、重放不重复添加。

长按用户气泡可选择存为候选。页面重新读取用户消息，较长消息只预填前100字并提示核对；可以截取原文，改写时使用手动整理。服务端要求来源存在、同用户同角色、确为用户消息且包含候选原文；AI输出不接受为事实来源。

资料原文来源可由服务端接口关联指定文档与消息序号；已有导入资料页面仍可手动关联整个文档，此时不能把人工总结标成逐字原文证据。截图识别仍先走原有授权、识别、归属核对与文字导入流程，不自动成为用户事实。

新建同主体、主题、内容的重复记忆返回原条目，不隐式确认、不增加条数。再次提供来源需明确编辑原条目并提交新来源与当前版本。

## 检查与删除

`companion.memory.inspect`是只读规则预览，不调用模型、不消费生成额度、不更新记忆。页面显示选用/未选用原因。预览输入为当前测试句；实际模型请求可能有不同上下文，因此真实请求另在`job.metrics.memorySelection`保留当轮结果。

实际请求只保存ID、版本、原因和分数组件，不复制私人事实原文；详细审计最多最近8次，并随48小时请求清理。删除记忆/资料会清除无效审计指针。角色事实删除继续按原有明确确认流程清空该角色旧正文，防止旧回复重新带回；若同样事实存在独立资料中，用户仍需清理该来源。

“查看来源”只读取本人当前角色的已关联消息，最多显示2000字。原消息到期或被清理后如实显示不可用，不会拿摘要冒充原文。手动整理和只关联整份资料的旧记录没有逐字原文证明。

未增加摘要或向量缓存，因此当前无需清理不存在的派生索引。后续引入时必须实现来源级联删除后才能发布。旧备份及用户自行导出文件不属于自动撤回范围，不宣称第三方已收到的数据可追回。

## 主动机制

普通与主动请求使用同一套记忆排序。主动请求按真实话题锚点检索，不能以空查询替代；身份仍由角色设定决定，不能把调度唤醒伪装为用户新发言。

副本支持最多连续3次主动尝试、5分钟间隔、每角色每日6次和北京时间23点至8点安静。明确输入、关闭、撤回授权优先；未发布前不得给旧角色静默开启后台模式。

失败或没有合适话题的后台会话延后1小时，防止每分钟堵住队头；如果用户新一轮消息已到，旧周期失败不能延后新周期。确定性请求ID、事务中的处理中状态以及提交前复核共同防重复。未知异常同样退避，不能无上限重放付费调用。

现有每次扫描最多处理一个候选，仍是小规模验证结构，不代表已支持全站30万次吞吐。没有新增用户指定年月日时分秒的任务队列，不承诺精确时间提醒。小程序后台生成不是微信联系人推送。

## 开源借鉴与许可

借鉴dsh-fish的事件、人格与唤醒分离，以及忙闲避让；借鉴dsh-memory-evolve的记忆候选、分轨和按需注入；借鉴WhaleMaid的决策与执行分离。这一版为本项目自行实现，未复制或运行第三方插件代码、宿主和外部账号工具。后续若直接改编源码，需要保留对应许可、版权声明与修改记录。

## 验证与后续工作

运行`node scripts/check.mjs`：类型检查、构建、Vitest、页面/JSON/前后端边界检查。新增测试见`tests/external-memory.test.ts`、`tests/autonomy.test.ts`及`tests/miniprogram.test.ts`。

本轮不增加模型真实调用，也未完成云定时器/真机验收；不能用Mock回复宣称GLM已完成这些质量测试。部署前需验证实际后台运行、开关/安静状态、双账号及角色隔离和真实记忆召回，记录失败样本。
