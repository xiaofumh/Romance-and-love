# V0.5.1 失败分析与修复

日期：2026-10-30，北京时间。默认12轮不变；已明确选择6轮的会话仍保留设置。本次不修改密钥、白名单、额度或审核策略。

## 已证实的问题

| 问题 | 原因与证据 | 修复 |
| --- | --- | --- |
| 读状态也可能与保存争写 | 原仓库的每次事务都执行整份用户文档set；允许重叠的事务测试中，8次只读查询出现DATABASE_TRANSACTION_CONFLICT。旧串行测试无法覆盖这个场景。 | 比较维护前后状态，只在变化时写入；新用户、过期清理、跨日额度及真实编辑仍写入。清理任务单独更新扫描时间，避免最旧一页阻塞后续记录。 |
| 模型成功后仍返回笼统服务不可用 | 原代码把SDK提交异常归入SERVICE_UNAVAILABLE；若记录失败状态也报错，后一个错误会覆盖原始错误。故障注入已复现。 | 分开数据库冲突、数据库不可用，保留失败阶段、固定错误类别和已返回token用量；二次保存失败保留原始错误，并只记录白名单诊断。 |
| 网络中断被报成格式错误 | 原JSON解析的catch同时覆盖响应体读取错误。 | 超时/中断与真实JSON、包络、大小错误分别分类；取消/释放流失败不覆盖主错误。没有自动重发模型。 |
| 隐式纠错漏入重点证据 | 三条高词法分数的旧事实会挤掉“不对，应该是青柠桥”这类零分纠错。相同输入旧版选[0,1,2]，新版选[1,2,3]。 | 仅在当前授权窗口中保守关联原用户主题及最新纠错，最多3条原文、时间排序；其他对象或话题切换截断关联。 |
| 话题/相处指令误判 | “别问我了”被当禁聊“我”；同消息事件未按顺序；转述跨逗号丢失说话人；恢复用语判定不一致。 | 共享分句与指令判定，区分转述，按原文顺序处理拒绝/重新许可；提问限制不禁止后续自我表达。 |

## 历史失败的证据边界

V0.5.0第一次真实主动接话的失败报告包含请求摘要及token用量，说明提供者已返回；但没有足够的失败阶段和SDK错误类别，因此不能把那一次历史失败唯一归因于数据库争写。本次修复的是可重复的缺陷，并补上后续诊断依据。不能据此声称所有偶发服务故障已经消失。

云开发官方说明确认：多个事务并发修改同一数据可能出现该错误，见[DATABASE_TRANSACTION_CONFLICT](https://docs.cloudbase.net/error-code/DATABASE_TRANSACTION_CONFLICT)和[事务说明](https://docs.cloudbase.net/database/transaction)。模型调用在数据库事务之外；没有新增可能重复计费的应用层自动重试。

## 验证与限制

本地完整检查：TypeScript、构建、305项测试、16页入口与前端边界均通过。新增并发测试使用MVCC故障假体，不等同于真实多账号压力测试。云端真实验收与部署结果另记于本次交付报告。

首组10轮真实调用的流程、纠错和状态检查通过，但人工发现首条回复夹杂异常字符，另有一条把第三方暂停表达接成了对用户的收尾，因此不能把该组计为回答质量全通过。为此补上发送给模型的本轮分句归属与转述说明，并增加精确确认文本的验收条件。原失败记录保留；不以字符串黑名单修饰答案、不自动重试或伪造固定回答。模型偶发乱码的唯一原因尚无足够证据确定，不能声称仅靠提示已彻底解决。

词法纠错和转述识别仍是保守规则，含糊指代可能无法关联。完整的授权窗口仍会发送给模型，重点证据不是额外的长期记忆。历史条目每条最多600个JavaScript长度单位、保存上限40条消息及30天边界不变。12轮是窗口上限，不保证所有细节均被准确回答。

保留V0.5.0源码和回溯包；V0.5.1不引入新的持久数据结构。源码回溯不等于还原已变更或已删除的用户数据。
