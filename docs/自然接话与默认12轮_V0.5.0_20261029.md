# V0.5.0：自然接话与默认12轮

日期：2026-10-29。目标工程项目根目录；沿用既有assistantApiV2、GLM-4.7、北京时间、白名单及额度。不引入新数据服务或第三方框架代码。

## 默认窗口

新会话明确保存contextRounds=12；旧会话未设置窗口时服务端默认12。明确设置6的旧会话保留6，可在设置切换。12轮按最近12条用户消息分组，包含对应普通回复及每轮至多一条主动消息，最多36条历史语义消息，再加本次输入。每条历史仍最多600个JavaScript长度单位，正文保存40条／30天。纠错、记忆关闭、删除和过期边界优先，不能承诺任何条件下都有完整12轮。窗口较长不代表通用召回率已被证明。

## 自然对话

移除聊天页相处状态栏及设置页倾听／轻松／暂停三按钮。保留角色的主动开关、自然语言暂停与恢复，不默认为旧角色开启主动。旧版interaction.configure接口兼容保留，暂停状态不因升级丢失。聊天页的AI身份与数据说明保留。

每次从实际选入且脱敏截短后的上下文重建临时话题提示，包括原文来源、当前话题候选、已问问题及拒绝话题。最长24小时且不能超窗口；不存新数据库字段、不做自动事实确认、不查窗口外内容。纠错后由原上下文边界自然清除，删除也不能从独立笔记复活。旧无时间消息不能作为主动话题来源。

真实测试发现长窗口内仍可能漏答，现将事实问答与话题引导分开：事实问题不附转场提示，并在请求末尾明确从当前窗口原文回答，历史“只回复收到”等仅约束过去那轮。简短回应及拒绝后的陈述约束也在末尾重申。异常think等生成标记整条拦截，不自动裁剪或付费重试；失败作业仅记阶段、分类和已有用量，不记录密钥或额外原始正文。

程序提供简短表达策略（回应问题、承接、简短回应、尊重边界、转场）和提问约束，GLM仍生成纯文本。原文不作为系统指令，明确更正及当前用户问题优先。停止把每轮都写成安慰加提问，不擅自编造现实经历或面试结果。自然分段仍是一次调用中的1至3段。

## 可等待的主动接话

删除五个固定话题轮换。只有存在新鲜、未尝试、未拒绝的当前话题来源，且最新用户消息不是简单应答、最近AI消息没有待答问号时，才可能进入模型。保留前台、空闲45秒、冷却5分钟、每用户轮最多一次尝试，以及草稿／隐藏页面／授权／额度保护。

模型可只返回[[WAIT]]；服务端拦截，作业标SKIPPED，不保存聊天正文、不显示内部标记，也不自动重试。该请求实际调用过模型，个人和全站额度均计数并记录token／耗时。模型前被阻止的不调用不计费。已经发起的供应商请求无法撤回费用；页面隐藏只阻止后续新发起。

## 借鉴与取舍

参考MaiBot的发言时机和自然聊天目标、SillyTavern的角色资料组织、Mem0的记忆生命周期思路，均未搬运代码或向其传输资料。保留现有云函数架构，不加入每轮多模型串联，不重新训练。

- https://github.com/Mai-with-u/MaiBot （仓库标GPL-3.0）
- https://github.com/SillyTavern/SillyTavern （AGPL-3.0）
- https://github.com/mem0ai/mem0 （Apache-2.0）

临时话题识别仍有规则边界，不能保证理解任意委婉拒绝或语义重复；模型需结合完整当前窗口补充判断。当前不做后台微信消息、长期跨窗口自动日程提醒，也不把AI包装成真人。
