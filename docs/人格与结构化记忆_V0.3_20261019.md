# V0.3 人格、历史参考与记忆纠错

用户仅选择两组增强：人格／称呼／关系／情绪，历史参考／事实记忆／纠错。没有开发语音、音色、真人联系人代发、待回复中心或服务端质量重生成；没有运行桌面EXE和安装脚本。

## 上下文准确口径

当前和本版都最多提交最近6轮历史，即12条user/assistant消息，加本次用户输入。每条历史消息最多600个JavaScript字符串长度单位；本次输入最多1200。保存最多20轮（40条消息）、最长30天不等于每次全量提交。模型自身容量不是此应用设定的上下文轮数。

另外附带选中角色的设定、最多10条有效且已确认的记忆、最多3组检索历史片段。记忆关闭、授权撤回、纠错、角色变更或过期会缩短可用上下文。不同会话的近期消息不混用；同角色可以共享其授权资料与确认记忆。每日30轮和全站每日300000次是额度，不是上下文。

## 人格与表达

沿用朋友／AI伴侣、原有性格、自定义设定及边界。新增称呼用户、自称、初识／熟悉／亲近、自然回应／温柔安慰／轻松俏皮／冷静认真，以及160字表达习惯。表达偏好不代表真实关系、心理诊断、额外权限或必然每次遵循。

字段为可选，旧数据只读不迁移、不删除；前端／提示词使用默认值。旧客户端省略新字段时不覆盖已有新设定。自由文本脱敏，所有角色内容仍为不可信资料，不能覆盖系统安全与AI身份规则。修改角色设定时保留旧聊天，但从下一轮停止提交修改前的消息，以免旧人设继续影响。

## 历史参考

资料详情显示双方消息数和同一说话人的重复内容数，重复只提醒、不自动清洗删除。原分页、1MiB限制、说话人核对和最多3组片段检索保留；不做未经授权的批量导入、模型训练或第三方历史上传。

历史文字、来源标注不能证明属于当前用户；确认事实优先于风格例句。不承诺能识别全部语义矛盾或完整读取整份历史。

## 结构化记忆与纠错

- 主体：我的事实、AI角色虚构设定、历史参考人物、未明确主体。旧条目默认主体未明确；新建关联文档候选默认参考人物，用户可核实后选择主体。
- 每条可填30字主题、100字正文、80字来源标注；来源标注不是系统核验。
- 有效期：长期、今天、7天。今天按北京时间午夜过期；服务端时间决定有效性。长期也会受关联资料删除／过期和用户删除影响，不保证永久。
- 先存候选，再手动确认；未确认和已过期记录不送模型。默认不自动开启记忆授权，也不把聊天或历史提取结果自动确认为事实。
- 对已明确主体且主题相同（NFKC规范化、忽略空格和大小写）的有效事实，若正文不同，阻止确认另一条；允许先存候选供检查。建议编辑原条目纠错。未填写主题、同义但不同主题及复杂语义矛盾仍需人工核对。
- 编辑后重新成为候选；确认使用乐观版本号防止旧页面覆盖新记录。确认、更改或首次发现过期时，在该角色会话设置上下文边界；旧消息仍可见，但不会在边界之后重新提交给模型。新的历史逐轮累积到最多6轮。
- 删除与纠错不同：沿用删除时清除该角色派生聊天正文的隐私策略；界面明确告知并要求用户确认。不自动执行用户数据删除。
- 在途回复遇设定／事实更改或过期时取消，迟到结果不落库；既有请求与计数不会因此重置。

## 兼容与验证

无需重设密钥、修改全站或个人额度、放开白名单或内容检查。代码中默认额度保持原值；实际云环境使用现有设置。保留原始文件在本轮暂存目录before-sync中；同步前比对哈希，若用户有重叠修改则停止覆盖。

新增专项测试覆盖旧数据、旧客户端、字段脱敏、主体区分、角色／用户隔离、来源归属、候选／确认、主题冲突、版本纠错、历史保留与上下文边界、北京时间过期、迟到答案取消、额度不变及6轮上下文截取。页面测试用SDK替身验证表单和人工确认回调，不等同真实微信授权或真实模型效果。

真实开发工具、部署、模型和预览结果以本轮交付说明为准。不能由单元测试推导“模型永不出错”，也不声称完成真实双账号、公开上线或高并发验收。
