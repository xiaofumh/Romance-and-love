# V0.4 连续相处、可控主动与6／12轮上下文评估

日期2026-10-24。用户明确要求开始研发，并保留当前V0.3.0可回溯；费用不是本轮优化优先项，但不等于无限调用、自动重试或自动提升额度。

## 已实现

- 保持AI身份与边界，在原人格、称呼、关系、情绪、表达习惯上加入持续相处策略。不只答题，也能轻松换话题、表达角色立场、尊重拒绝；不编造真实身体、现实行动或参考人物身份，不用冷落／内疚／吃醋施压。
- 轻量状态只有listening／light／quiet，来自用户明确表达与可控规则，不声称准确识别心理状态；“晚安／不想聊／别主动”等暂停主动，下一次用户消息可恢复。
- 自然气泡由模型用空行分段，最多3块；短回复不强行拆分，代码块保持整段。仍一次模型请求、一个语义assistant消息，原文可完整复制，旧客户端仍读text。无伪造输入中或随机打字延迟。
- 主动接话默认关闭；用户在角色页明确开启后，只在真实云端聊天页可见、无输入草稿、无普通在途发送、已有可用用户历史且本地空闲至少45秒时请求。两次主动尝试至少间隔5分钟，每条用户消息之后最多尝试一次。服务端再次检查身份／归属、原授权、开关、quiet、时序、幂等、模型开关、白名单及限额。
- 主动请求不伪造user消息；成功仅新增assistant.kind=initiative并标记“AI主动接话”。失败不自动重试，网络丢响应时不声称云端一定没执行；用户可重新进入查看。写草稿不会被清空，生成中仍可输入草稿。
- 页面隐藏或卸载清除尚未发起的计时器；已交给服务商的请求可能继续处理，不能承诺撤回。没有后台监听微信、退出后推送、主动营销、真人联系人代发、语音或音色功能。

## 上下文

旧会话默认6轮窗口（最多12条历史消息），可在会话设置选择12轮窗口（最多24条）；每条历史仍最多600个JavaScript长度单位，加本次普通输入。主动消息也占窗口条数，因此完整用户对话轮数可能更少。多气泡不增加语义消息或调用次数。

保存最多40条、最长30天不变。最多10条有效确认记忆与3组历史片段不变。纠错、停用记忆、过期和角色变更的边界优先于窗口变长；不混用其他会话短期消息。更长不保证更准确，长期事实仍需可纠正记忆。

窗口修改需要明确确认及乐观设置版本，取消当前账号在途生成，不重置日计数；当前版本默认仍6轮。companion.conversation.fork只复制当前用户可访问的源会话快照，独立新ID、窗口和后续历史；不能跨用户，源会话在途生成时拒绝建立对比。该能力由对比脚本使用，不自动复制私人资料。

## 评估方法

scripts/context-comparison-live.mjs必须显式带--real-synthetic。最多计划16次真实请求：12轮虚构历史、相同快照的6／12轮各一次相同问题、一次自然私聊和一次主动接话。开始前检查原授权及个人剩余额度，不修改密钥、白名单、记忆开关或个人／全站限额。失败停止，不默默重试；只清理该脚本创建的临时角色及其数据。

两分支核验原始历史哈希相同。目标只在第1轮出现，不写入长期记忆／参考资料；检查填充回答是否复述目标而污染窗口。保存实际historyMessages、服务商返回的输入／输出Token和服务端／端到端耗时；缺失usage不虚构零Token。一次配对不能推断统计显著性、普遍人格质量、金额费用或所有场景12轮都更好。

普通回复和主动回复都受既有个人每日成功次数与全站调用尝试约束；质量／传输失败可能产生费用，记录不是人民币账单。不为费用优化牺牲必要上下文，也不跑30万次压测。
